# miniboos 协作机制（一人公司章程 2.0）

> CEO棍儿哥 × AI技术部 | 定稿：2026-09-16 | 本档是"我们怎么合作"的宪法，谁犯迷糊翻谁

## 一、角色分工

- **AI起草一切**（PRD/设计规范/技术文档/代码），**CEO只做五件事**：①业务三问口述（不可外包）②审稿 ③拍板 ④本人专属动作（账号/密钥/答辩）⑤验收
- 对话框=指挥通道；文档=落地凭证；git commit=变更史。**口说无凭，文档为证**

## 二、变更三级制（核心机制）

| 级别 | 什么算 | 流程 | 文档动作 |
|---|---|---|---|
| **L1·微调** | 颜色/间距/文案/小交互 | 对话框说 → AI直接改码 → CEO刷新验收 | 不动文档 |
| **L2·重构** | 页面重设计、功能行为改变 | 对话框说意图 → **AI先改文档 → CEO确认 → 再改码** → CEO验收 | 设计规范/PRD对应条目同步 |
| **L3·新增** | 新功能模块、业务规则变更 | CEO提需求 → AI出**变更提案**（PRD影响+表结构+工作量）→ CEO拍板 → 排期改码 → 验收 | PRD升版本（v1.2/v1.3…），变更记录留痕 |

## 三、功能缺口分类（"简陋感"的处理法）

| 类别 | 定义 | 处理 |
|---|---|---|
| **A类·功能缺口** | PRD承诺了但没做/没做好 | v1必须修（例：HR查简历，2026-09-16已补） |
| **B类·增强项** | PRD未承诺，做了更好 | 进v2清单（PRD演进节），不阻塞上线 |

## 四、UI协作语言（CEO不需要会设计）

- **参照物**："做成XX App那样"（当前参照：BOSS直聘，2026-09-16拍板）
- **选择题**：AI出多版候选，CEO挑+微调指令（"这个方向对，再亮一点"）
- 管理后台参照：腾讯云控制台/公众平台/Element官方demo——后台要效率不要个性
- UI验收的尺子=《UI设计规范》（见姊妹文档），不达标要能指出违反哪条

## 五、验收节奏

1. 功能验收：按PRD功能条目逐条点（19条）
2. UI验收：按《UI设计规范》对照
3. 修复循环：CEO提意见（标L1/L2/L3）→ AI修 → 复验 → 直至点头
