# ADR-001：生产部署与数据库选型

| 项 | 值 |
|---|---|
| 状态 | **已采纳**（CEO终裁） |
| 决策人 | 棍儿哥（CEO） |
| 日期 | 2026-09-16 |
| 关联 | PRD v1.0 第6节（技术架构）、第8节（非功能需求） |

## 一、决策背景

- 约束：全链路0元（PRD第8节成本红线）；技术栈写死 Java + Vue3 + MySQL；生产链路目标7×24在线（keep-alive保活，PRD已立项）
- 议题：① Java后端部署在哪 ② 生产MySQL放在哪

## 二、决策结论（甲+备份机器人）

| 组件 | 选型 | 要点 |
|---|---|---|
| 后端托管 | **Render 免费层** | 750实例小时/月>744h，单服务7×24够用；512MB/0.1CPU |
| 生产数据库 | **TiDB Cloud Starter** | MySQL协议兼容；免费5GiB行存+5000万RU/月；**不绑卡**（超额暂停而非扣费=物理断路器） |
| 保活 | **GitHub Actions cron**，每10分钟GET `/api/health` | 公开仓库Actions免费；间隔留余量防cron延迟偷渡休眠 |
| 数据安全 | **备份机器人**：每日定时备份TiDB数据到GitHub仓库 `backups/` | todo-practice同款模式复用；断供兜底=换免费库+备份恢复 |

## 三、探测数据存档（2026-09-16侦察）

- Render：750h/月、15分钟无流量spin down、Spring Boot官方支持、口碑3.6★(122评)
- Koyeb：1免费实例、**1小时**无流量才缩容、512MB/0.1vCPU/2GB SSD、区域仅法兰克福/华盛顿、口碑3.1★(29评)
- TiDB Cloud Starter（原TiDB Serverless）：5GiB行+5GiB列+50M RU/月、最多5免费集群、免信用卡
- 付费行情：PlanetScale $5/月起（2024-04取消免费层）；腾讯云/阿里云RDS MySQL约30~100元/月（新用户试用1-3个月到期转付费）

## 四、落选方案存档（防翻烧饼）

| 方案 | 落选原因 |
|---|---|
| 乙：Koyeb | 可用，但口碑低于Render；"1小时才休眠"优势在保活方案面前无价值 |
| 丙：全本地+内网穿透 | 你关机=生产全断；keep-alive失去意义；"真上线"成色最低 |
| 混搭：云后端+本地库 | **工程死结**——云容器连不进家庭内网（架构铁律：后端在哪，库跟到哪） |
| 付费RDS / PlanetScale | 撞0元红线 |
| 本地库"省预算" | 事实纠正：TiDB免费层=0元，不构成预算负担 |

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| 512MB内存跑Spring Boot紧约束 | JVM参数限堆（-Xmx~320m）+精简依赖；第3关落实并实测（社区有大量成功先例） |
| `*.onrender.com` 大陆可达性不稳 | 仿真阶段达标线=海外可达（同EdgeOne逻辑，Actions侦察兵验收）；他本人网络可顺手实测，通=白赚 |
| TiDB供应商断供（PlanetScale前科） | 每日备份到GitHub=数据钥匙在手；断供损失=搬库半天，非数据 |
| TiDB"MySQL兼容"非原生内核 | 驱动/协议/SQL层与MySQL无差别（Java代码零改动）；极端高级特性有微差，本项目CRUD+索引不涉及 |
| Render 750h额度仅够单服务 | 本项目只部署1个后端服务（三个前端站在EdgeOne），不超编 |
